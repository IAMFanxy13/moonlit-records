# 歌词驱动的电脑键盘钢琴：产品设计规格

日期：2026-08-12  
状态：设计方向已获用户确认；第一阶段 Web MVP 待实施

## 1. 产品定义

这是一个桌面优先、直接运行在现代浏览器中的 Web 钢琴应用。用户在电脑上搜索歌曲，或上传歌曲音频/视频；应用把歌词和主旋律转换成一系列电脑键盘提示。用户必须亲自按键才会发出钢琴声，歌曲不会随时间自动演奏。网页不要求安装 ROG 驱动、浏览器扩展或桌面客户端。

产品的核心不是传统的“电脑键固定对应音高”，也不是要求用户认识钢琴键，而是“双层按键解析”：

1. 每个可演奏的电脑键都有一个长期固定的默认钢琴音，可用于自由即兴。
2. 当某个键成为当前歌词的目标键时，它只在当前步骤临时变为该歌词在原曲旋律中需要的钢琴音。

示例：默认 `N = E4`。歌曲进行到“你”时，事件为 `你 → N → G4`；此时按 `N` 播放 `G4`。事件结束后，`N` 恢复为 `E4`。

## 2. 设计来源与借鉴

本设计吸收下列成熟思路，但不直接复制任何单一产品：

- [AutoPiano](https://github.com/AutoPiano/AutoPiano)：固定的电脑键到钢琴音映射，作为自由弹奏的基础层。
- [Synthesia](https://synthesia.app/about)：明显的下一音提示、练习状态和曲库体验。
- [Piano Genie](https://magenta.withgoogle.com/pianogenie)：控制器按键根据音乐上下文动态输出音符；本产品改为由确定的歌曲数据驱动，而不是让模型预测音符。
- [MusicXML](https://www.w3.org/2021/06/musicxml40/tutorial/midi-compatible-part/)：歌词、音高、时值和音符之间的结构化绑定。
- [Demucs](https://github.com/facebookresearch/demucs)、[Whisper](https://github.com/openai/whisper) 和 [Basic Pitch](https://github.com/spotify/basic-pitch)：分别提供音源分离、歌词转写和音频转音符的成熟技术路线。
- [Tone.js Sampler](https://tonejs.github.io/examples/sampler) 与 [Tone Piano](https://tambien.github.io/Piano/)：浏览器内低延迟、多采样钢琴播放。

视觉与交互还吸收下列成熟经验，但不复制它们的具体页面：

- [MotionSites](https://motionsites.ai/)：一个强视觉焦点、克制导航、模块化页面结构，以及只服务于层级的背景运动。
- [小红书 RPDC](https://rpdc.xiaohongshu.com/home)：编辑式大字、留白、封面感与更亲密的内容语气；其 52 个设计原则用于约束映射、反馈、信噪比和渐进呈现。
- 抖音/TikTok 与 Instagram 的音乐交互：一屏聚焦、按下即反馈、声音驱动的短动效，以及可分享的完成卡片；不引入无限信息流、点赞评论和成瘾性滚动。

最终视觉方向命名为“月光唱片”：深夜酒红、暖象牙、低饱和金色组成固定主色，搭配唱片封套式排版、轻微纸张/黑胶材质和随琴声短暂呼吸的光晕。高级感来自字体、比例、留白、材质与动效时机，不使用满屏玻璃卡片、持续粒子、廉价霓虹或游戏化失败惩罚。INFJ 仅作为偏好线索：强调安静、诗性、意义感和私人空间，但不以人格标签替代清晰易用的交互。

MotionSites 在本项目中是“设计提示词与模块思路来源”，不是运行时组件依赖。可把免费或已授权的完整提示词交给编码代理生成 React/CSS 初稿，再按本规格改写和测试；不直接复制未授权的付费提示词，不热链其演示视频，也不让模板自带的营销页结构主导演奏产品。MotionSites MCP 属于可选的设计检索入口，不是应用上线所必需的服务。

本产品的独特组合是：固定自由弹奏层、由歌词和原曲旋律驱动的临时覆盖层、电脑字母提示，以及“错误键可以即兴发声、只有目标键才推进歌曲”的等待式体验。

## 3. 目标与非目标

### 3.1 目标

- 不懂乐理的用户也能按照歌词和字母提示演奏歌曲主旋律。
- 所有琴声都由真实按键触发；不按键时绝不发出琴声，也不推进歌曲。
- 屏幕显示通用 QWERTY 键盘，不依赖华硕 ROG 或任何品牌的键盘灯光、驱动程序和硬件接口。
- 通过搜歌提供最方便的入口，同时允许上传音频或视频扩充个人曲库。
- 使用真实钢琴采样，允许自动推荐和手动切换钢琴类型。
- 在不同品牌电脑的常用 Windows 浏览器上保持一致行为。
- 演奏页始终保持高级、安静和聚焦；复杂功能退居搜索、曲库和设置页面。

### 3.2 非目标

- 不控制物理键盘灯光。
- 不在无人按键时自动播放旋律或伴奏。
- 不设置节拍限时、生命值、强制失败或惩罚性反馈；虽然目标键必须弹对才推进，但用户可以在等待目标键期间自由即兴。
- 不承诺能够未经授权地直接获取任意商业歌曲的音源或乐谱。
- 第一版不尝试完整还原多轨伴奏；演奏目标是清楚、可靠的主旋律。

## 4. 用户流程

### 4.1 搜索优先

首页以一个大搜索框为主。用户输入歌名后，结果按歌名、歌手、版本和时长区分，避免现场版与录音室版混淆。结果包含三种状态：

- **可立即演奏**：已经生成并校验歌曲数据，点击即可加载。
- **需要生成**：识别到歌曲信息，但没有可演奏数据；用户补充音频或视频后生成。
- **生成中/生成失败**：显示明确阶段和可恢复操作，不把失败伪装成可演奏结果。

已生成歌曲保存到个人曲库，下次可直接搜索打开。公共曲库仅接受来源和授权允许的歌曲；用户上传内容默认私有。

### 4.2 上传生成

用户可上传常见音频或视频文件。处理过程显示真实阶段：

1. 提取并规范化音频。
2. 分离人声与伴奏。
3. 识别歌词和歌词时间位置。
4. 提取人声主旋律及音符事件。
5. 对齐歌词、音符和乐句。
6. 清理呼吸声、短暂噪声、错误八度和过度细碎的颤音。
7. 生成字母键位、钢琴推荐和质量置信度。
8. 打包并缓存为可演奏歌曲。

自动识别允许存在误差，但必须可降级：高置信度事件直接使用；低置信度事件选择更稳定的主旋律候选并标记；某一局部失败不得阻止整首歌生成。若歌词识别完全失败，可让用户粘贴歌词后重新对齐；若旋律识别完全失败，则明确提示换用更清晰的音源。

### 4.3 开始演奏

应用必须先加载所选钢琴采样，再显示“点击开始”。该点击同时满足浏览器音频必须由用户手势启动的限制。加载完成前不能进入一个看似可弹、实际第一声丢失的状态。

## 5. 演奏事件与歌词映射

歌曲被转换成有顺序的 `SongEvent` 列表。每个事件至少包含：

- 所属乐句编号；
- 当前歌词字或占位符；
- 屏幕提示键；
- 需要播放的钢琴音高；
- 建议力度；
- 原音频中的开始、结束时间，仅用于提取和回看，不用于自动推进；
- 识别置信度。

映射规则如下：

- 中文歌词使用当前读音的拼音首字母，例如 `你 → N`、`好 → H`。
- 一个中文歌词字对应多个旋律音时，复制为多个事件并重复提示同一个字母，例如 `爱 → A A A`。
- 英文歌词以每个单词的首字母作为提示键，例如 `I love you → I L Y`；一个英文单词跨多个旋律音时，同样重复该单词的首字母。
- 标点符号不生成事件。
- 无歌词但需要用户演奏的主旋律事件使用空格键，歌词区显示 `♪`。
- 事件以主旋律单音为主，不在第一版自动加入复杂和弦。

## 6. 双层按键解析规则

### 6.1 默认音层

所有“可演奏普通键”都有稳定的默认音，且同一物理位置在受支持的电脑上保持一致。使用物理键码而不是输入法输出字符识别按键，以免中文输入法、Shift 状态或大小写改变演奏结果。

- 反引号/数字排优先按照白键音阶排列；如果某浏览器或系统保留某键，则从可演奏集合中排除并在屏幕键盘上置灰。
- `Esc/F1…F12` 仅在浏览器能够可靠阻止其默认行为、且不会造成退出全屏、帮助页、刷新、开发者工具、亮度或音量等冲突时使用。第一阶段默认不把这排设为歌曲目标键，并把冲突键置灰；黑键音高由其余安全键位补充。
- 字母、数字、常用标点和空格映射到预设音域；Tab、Caps Lock、Enter、Backspace 等可能改变焦点、提交表单或导航的键只有在演奏页能够可靠拦截时才加入可演奏集合。
- 自由弹奏允许同时按多个普通键形成和弦。

`Fn` 通常不会被操作系统上报，`Windows`、`Ctrl`、`Alt` 等键会触发系统级行为，因此不作为歌曲目标，也不承诺捕获。`Esc` 与功能键默认同样不作为歌曲目标。可演奏集合由显式白名单定义，而不是“能收到 keydown 就全部捕获”；这一限制保证产品不依赖特定品牌硬件，也不会破坏常用浏览器操作。

### 6.2 当前歌曲覆盖层

设当前事件目标键为 `targetKey`，目标音为 `songNote`：

- 按下 `targetKey`：播放 `songNote`，显示正确反馈，消费当前事件并进入下一事件。
- 按下其他可演奏键：播放该键的默认音并显示错误反馈，但不消费当前事件；当前目标键保持高亮，用户可以继续按任意普通键即兴，直到按下 `targetKey`。
- 当前事件结束后，`targetKey` 立即恢复默认音；下一事件可再次覆盖同一键或另一个键。
- 非可演奏系统键不消费事件。
- 操作系统产生的长按重复事件必须忽略；用户需要松开并重新按下才产生下一次演奏。
- 同时按下多个键时，以浏览器收到的独立物理按下顺序逐个处理事件。

### 6.3 暂停状态

暂停后歌曲事件不再推进，但普通键仍播放默认音，用户可以自由即兴。用户可继续、重来当前句、重来整首或手动回退。演奏中按错也不会回退：歌曲本来就停留在当前事件，直到目标键被按下。

## 7. 钢琴声音设计

第一版提供四类真实采样钢琴：

- 音乐会三角钢琴：古典、宏大、动态范围大的歌曲。
- 明亮三角钢琴：现代流行和节奏清晰的歌曲。
- 温暖柔和钢琴：慢歌和抒情歌曲。
- 立式钢琴：民谣、怀旧和亲密感较强的歌曲。

系统根据速度、能量、主旋律音域、亮度和风格标签给出推荐，用户可随时手动切换。切换时先后台加载新采样，完成后再无缝启用。

声音引擎要求：

- 使用多音高采样并对缺失音高进行有限变调，而不是用单个样本覆盖全音域。
- 支持复音、自然衰减、松键尾音和适量混响。
- 电脑键盘没有力度感应：歌曲模式使用歌曲事件的建议力度，自由弹奏使用稳定的中等力度。
- 选定钢琴必须在演奏开始前预加载；预加载完成后，按键到发声不应有明显可感延迟。
- 切换页面或暂停时正确释放持续声音，避免卡音。

## 8. 屏幕布局与视觉反馈

演奏页分三层：

1. 顶部：歌名、歌手、歌曲版本、当前钢琴、进度，以及暂停、重来和切歌操作。
2. 中部：KTV 式歌词固定显示正在演奏的当前句和紧接着的下一句；当前句逐字点亮，当前字放大并在下方明确显示目标键。上一句只在换句时短暂淡出，不长期占据主阅读位置；下一句始终可提前阅读。
3. 下部：通用 QWERTY 屏幕键盘，按实际键宽和错位关系绘制，而不是整齐网格。

状态反馈：

- 当前目标键使用高亮呼吸边框。
- 按对后该键短暂变绿并显示 `✓`。
- 按错后实际按下的键短暂变红并显示 `×`；当前目标键和当前歌词仍保持高亮，不切换到下一目标。
- 颜色之外必须同时使用图标、轮廓和文字，保证色觉差异用户仍能判断。
- 动画应快速、克制，不能延迟下一步输入。

视觉层级与动效约束：

- 歌词是情绪中心，屏幕键盘是操作中心；任一时刻只能有一个最强高亮目标。
- 声音触发后才出现光晕、字色推进和按键反馈；不演奏时背景只保留极慢、低对比度的呼吸。
- 正确反馈使用暖金/象牙色短暂增强，不使用竞技式大面积绿色庆祝；错误仍以红色、`×` 和轮廓变化明确表达，但不播放额外刺耳提示音，错误音就是实际按错键的默认钢琴音。
- 演奏结束生成唱片封套式纪念卡，包含歌曲、日期、正确/错误数和错键位置；它可以保存或分享，但演奏页不展示社交计数。
- 桌面宽度低于 `768px` 时隐藏演奏键盘并提示“演奏需要实体电脑键盘”；手机端仅支持搜歌、试听元数据和管理个人曲库。

只有演奏页拥有键盘焦点时才捕获按键，搜索框、文本输入和系统快捷键不受干扰。页面失去焦点时自动暂停，避免切换窗口过程中误跳歌词。

演奏结束显示正确数、错误数和发生错误的歌词位置，但不设置失败、生命值或强制过关。

## 9. 系统边界与组件

系统拆为六个可独立测试和替换的模块：

1. **歌曲目录与搜索**：管理公开曲库、个人曲库、版本和处理状态。
2. **音视频生成管线**：异步执行提取、分离、识别、对齐、清理与质量评分。
3. **统一歌曲数据包**：向播放器提供与来源无关的元数据、歌词、乐句、事件和音色推荐。
4. **演奏状态机**：只负责当前事件、正确/错误判断、消费规则、暂停和回退。
5. **屏幕键盘与歌词界面**：渲染物理布局、目标、按下状态和反馈，不自行决定音高。
6. **钢琴声音引擎**：加载采样并按照音高、力度、按下和松开事件发声。

推荐部署形态为可托管的纯 Web 前端，配合服务端搜索、存储和异步音频处理任务。这样普通电脑只需 Chrome 或 Edge 即可演奏，耗时的模型处理可放在有合适算力的服务器或专用工作节点上。第一阶段先交付使用内置校验曲包的完整前端闭环；搜索接口、曲包接口和生成任务接口保持独立，使后续服务端接入不需要重写演奏器。

## 10. 错误处理、隐私与版权

- 不支持的文件格式、文件过大、音轨缺失和处理失败必须给出可行动的中文提示。
- 处理任务可以安全重试；相同文件不重复生成，优先复用已经完成的个人结果。
- 局部低置信度不阻断全曲；完全无法获得歌词或旋律时才判定失败。
- 上传内容默认私有，并提供删除个人歌曲及其源文件的能力。
- 公共曲库不从流媒体平台擅自下载歌曲；搜索到元数据但没有合法可用的演奏数据时，进入“需要生成”流程。
- 原始上传文件和生成数据应分开存储，便于用户删除源文件但保留其个人演奏数据，或彻底删除二者。

## 11. 测试策略

### 11.1 单元测试

- 默认键位映射稳定且无重复配置错误。
- 拼音首字母、英文首字母、标点忽略、拖腔重复和无歌词空格规则正确。
- 正确键会推进；错误键发声和记录但不推进；系统键、长按重复、暂停和恢复的状态转移正确。
- 当前事件结束后临时覆盖必定清除。
- 乐句回退和整首重来恢复到确定状态。

### 11.2 集成测试

- 搜索结果状态到演奏页的完整流转。
- 上传任务各阶段、失败重试、缓存命中和个人曲库复用。
- 歌曲数据包能够在不依赖生成来源的情况下被播放器加载。
- 四种钢琴采样加载、切换、复音和声音释放。
- 页面焦点变化时自动暂停，文本输入时不触发琴声。

### 11.3 端到端与人工听感测试

- Windows Chrome 与 Edge。
- 常见笔记本和外接 QWERTY 键盘；不要求 ROG 灯光或驱动。
- 短歌、长歌、快歌、慢歌、拖腔、重复字母、纯器乐小节和同名不同版本。
- 用人工试听检查明显错八度、呼吸声误判为音符、歌词错位和首键延迟。

## 12. 验收标准

产品达到可交付状态必须同时满足：

1. 不按键时没有琴声，歌曲事件也不推进。
2. 按对键播放当前歌曲旋律音并进入下一事件；按错键播放错误键默认音并标红，但当前目标与歌词位置保持不变。
3. 只有正确目标键消费当前事件；错误键可以连续用于即兴，直到目标键被按下。
4. 长按不连续推进；松开再按才产生新事件。
5. 临时歌曲音只在对应事件存在，事件结束后恢复默认音。
6. 一个歌词字多音时能以重复按键逐音演奏；无歌词旋律使用空格。
7. 搜索可区分立即演奏、需要生成、生成中和失败状态。
8. 上传音频或视频可以生成统一歌曲数据包；局部低置信度不会令全曲失败。
9. 四种钢琴可自动推荐、预加载和手动切换。
10. 页面失焦自动暂停；暂停时可以用默认音自由弹奏。
11. Chrome/Edge 上的通用 QWERTY 键位、声音和状态行为一致。
12. 已预加载的钢琴在普通电脑上没有明显可感的首键延迟或卡音。
13. 演奏页固定显示当前句与下一句；当前字、目标键和下一句在 `1366×768` 视口内无需滚动即可同时看见。
14. 浏览器/系统冲突键默认置灰且不会被歌曲选作目标；演奏不会触发刷新、帮助页、退出全屏或页面导航。
15. `360px` 手机视口不显示可演奏键盘，并明确说明需要实体电脑键盘；搜歌与曲库信息仍可阅读。
16. 初始静止、正确、错误、换句和完成五种状态都符合“月光唱片”视觉方向；动效尊重 `prefers-reduced-motion`。

## 13. 实施顺序建议

为减少把复杂识别问题与演奏问题混在一起，建议按以下顺序实施：

1. 统一歌曲数据包、演奏状态机、屏幕键盘和一种钢琴音色。
2. 内置少量已校验歌曲，完成搜索与完整演奏闭环。
3. 增加四种钢琴、自动推荐、个人曲库和缓存。
4. 接入音频/视频生成管线与后台任务状态。
5. 扩大合法曲库、改善低置信度修正和跨设备体验。

每一阶段都保持前一阶段可独立演奏和测试，不以尚未完成的自动识别阻塞核心钢琴体验。
